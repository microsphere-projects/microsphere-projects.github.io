Dependencies & BOMs ​

Every artifact uses the Group ID io.github.microsphere-projects and is published to Maven Central.

Why each project has its own BOM ​

Microsphere uses per-sub-project BOMs rather than one giant BOM. Each sub-project targets a different Spring generation and they do not share a release cadence — microsphere-spring may be at 0.2.39 while microsphere-i18n sits at 0.2.21. Managing them separately lets each BOM evolve independently, and you import only what you need.

If you want to align several sub-projects at once, import multiple BOMs; Maven resolves them in declaration order.

kotlin
dependencies {
    implementation(platform("io.github.microsphere-projects:microsphere-java-dependencies:$msJavaVersion"))
    implementation("io.github.microsphere-projects:microsphere-java-core")
}

Inheriting the parent POM ​

If you are developing a Microsphere sub-project itself, inherit the shared parent POM to get the full build setup:

xml
<parent>
  <groupId>io.github.microsphere-projects</groupId>
  <artifactId>microsphere-build</artifactId>
  <version>${microsphere-build.version}</version>
</parent>

See microsphere-build.

Excluding dependencies ​

Auto-configuration exclusions merge

microsphere.autoconfigure.exclude merges exclusions from multiple configuration sources, while Spring Boot's native spring.autoconfigure.exclude replaces them. If you declare exclusions in more than one place, prefer the former.
